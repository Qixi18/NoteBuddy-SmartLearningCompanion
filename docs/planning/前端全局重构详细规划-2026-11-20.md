## 1. 决策与范围

采用五个主要页面：开始、学习要求、已有表现、学习建议、案例与交付。三个分析页面共享工作上下文；页面顶部持续呈现证据链摘要。用户可以自由切换，不使用必须逐步点击才能前进的强制向导。

主使用者按教师或承担教师复核职责的演示人员设计。学生可以阅读已复核方案中的学习任务和提示，但本轮不建设独立学生账户、答题系统或学习管理平台。评审通过同一真实工作流程观看功能，不另建只展示静态结果的演示系统。

本轮完成范围：导航、页面职责、信息层级、共享选择状态、证据查看、建议阅读与编辑、案例与导出组织、异常状态、响应式与键盘操作。复用现有 React/TypeScript/Vite、API 和业务规则。

不扩展历史批次管理：当前 client 提供读取当前运行与新建导入的接口，没有已确认的历史运行列表/切换契约。首页显示“当前批次”和“导入新数据”，不显示无法工作的“最近分析”“更换历史批次”。重新加载当前运行不等于支持任意历史运行恢复。

纠正前次对话线稿：DC01、DC02 是模拟班级编号；测验节点从 `run.nodes` 读取，绝不硬编码为 DC01/DC02。D01—D40 是学生编号范围，不用作批次名称。所有线稿中的数量与结论使用占位符，正式页面只显示真实接口数据。

| 当前问题 | 调整 | 预期作用 |

## 3. 信息架构与路由

```text
智慧学伴
├─ 开始 /home                    当前批次、导入、继续当前分析
├─ 学习要求 /requirements        主题、指标、题目联系、来源核验
├─ 已有表现 /performance         班级比较 / 学生分析
│  ├─ 作答证据                   当前范围的详情面板，可定位记录
│  └─ 数据质量                   辅助核查视图，支持直接链接
├─ 学习建议 /recommendations     阅读方案 / 编辑复核 / 观察与调整
└─ 案例与交付 /cases             案例准备 / 阅读报告 / 交付检查
```

保留轻量 hash 导航，不为此次改版引入路由框架。旧路径映射：knowledge/indicators → requirements；insights/classes → performance 的班级视图；insights/students → 学生视图；insights/evidence → 学生视图并打开证据；insights/quality → 质量视图；plan/reviews → recommendations；plan/adjustments → 建议页的观察与调整；plan/cases → cases。旧 knowledge/sources 别名继续兼容。

URL 只保存页面与必要选择 ID，例如节点、指标、学生、局部视图和证据定位，不保存作答正文、教师未保存文本或模型内容。解析后校验 ID 属于当前运行；过期参数给出说明，不能静默换成另一个学生。浏览器前进/后退恢复选择与视图。

## 5. 状态、数据与交互契约

共享范围：`runId + nodeId + indicatorId + classId + studentId`；学生推导所属班级，班级切换时不得保留不属于该班的学生。班级是浏览过滤条件，不新增到现有个人草稿请求中。要求页只需要运行和指标，不强制节点/学生。

局部视图：表现页班级/个人/质量、证据定位；建议页阅读/编辑/观察；交付页准备/报告/检查。草稿和未保存编辑使用运行、学生、指标、节点作为完整键，不使用仅学生和指标的键。

切换规则：

1. 同一范围切页保留当前选择；刷新后优先恢复 URL 中合法范围。未保存正文不写入 URL 或默认持久化到浏览器。
2. 切换运行清空旧草稿、编辑、案例选择、证据定位和预检；重新获取服务端事实。
3. 切换学生/节点/指标时，先处理未保存编辑；旧异步响应不得覆盖新范围。
4. 来源核验或复核保存后刷新关联阅读内容；历史仍可访问，已失效材料不维持“已核验”外观。
5. 局部接口失败只影响对应区域；明确失败与无数据的区别，提供重试，保留可用区域。

| 状态 | 页面行为与下一步 |
| --- | --- |
| 无数据 | 只展示导入引导，不出现空白统计卡 |
| 未选节点/学生 | 说明所需选择；不默认替用户作出教学对象选择 |
| 来源待核验/变化 | 就近标状态，提供核验入口；禁止当作正式资源 |
| 无有效评分 | 分开显示可见记录状态，允许补充观察建议 |
| 生成处理中 | 锁定当前生成动作，允许浏览，范围变化后结果隔离 |
| 保存失败 | 保留编辑内容与失败提示，允许重试 |
| 导出受阻 | 显示具体检查项和可返回的修复入口 |
| 内容过长 | 正文换行、按需展开；不以省略号隐藏唯一证据 |

## 7. 视觉、响应式与无障碍

延续项目现有克制配色和组件，不新增 UI 框架或动画库。优先级通过位置、字重、留白与标题组织建立。主屏突出可读结论和下一步，ID、版本、哈希等进入证据详情；关键范围、来源状态与限制始终可见。

1440/1920 像素适合目录与详情并列；1280 像素压缩留白、仍保留主操作；1024 像素证据详情转全宽、双列方案转单列，避免正文窄到逐字换行。更窄窗口允许导航换行和表格局部横滚，不承诺完整手机工作台。长题干/作答必须可阅读，不为截图整齐删除内容。

所有交互可键盘操作；详情打开后移动焦点、关闭后回到触发按钮；Escape 关闭详情且不丢编辑。状态有文字，不只用颜色。错误与保存结果可被辅助技术播报。页面切换将焦点放到标题，保留可预期的后退行为。

## 8. 实施顺序与阶段退出条件

1. **结构与范围**：路由、外壳、五页装配、共享范围和旧链接。退出条件：跨页与浏览器返回保持正确对象；旧链接可用；旧请求不污染新范围。

## 13. v1.1 审查修订与执行补充

本节处理初稿存在的范围歧义和落地缺口；同一事项按本节明确规则执行。

### 13.1 分析范围与交付范围分开管理

个人建议以单一运行/学生/指标/节点为范围；交付上下文以运行、三名学生、班级报告节点为范围。当前 `caseReports(students)` 并不接收节点参数，案例依据来自保存的 evidence_refs/review_refs。因此班级节点只约束班级报告，不能过滤掉个人案例中合法引用的其他节点。

`useReleaseSelection` 放在 App 持续存在的层级，修复问题时离开 CasesPage 也保留选人和班级报告节点。刷新恢复只可使用 URL 中绑定 run_id 的合法 ID，不存正文；run_id 不匹配时提示重新选择。修复跳转携带返回局部视图及检查项，不使用只有组件挂载时才存在的 DOM ID 跳转。

“加入案例准备”只将当前学生加入待选集合并跳转；不自动创建正式案例、不代签复核、不自动确认代表性。重复选择提示已加入，已有三人时让用户明确替换，不能自动挤掉旧案例。案例编辑中的指标/节点只用于挑选引用，不改写其他已保存引用的范围。

### 13.2 补足当前契约与线稿之间的差异

`TeachingPlanV2.steps` 是字符串数组，`resource_reasons` 是材料级理由，没有可靠的逐步骤材料映射。v1.1 已将线稿改为步骤、材料理由、总体复核理由三个分区；不得按数组位置配对，或让前端猜测每步对应的资源。若以后确需逐步骤映射，应作为明确的 schema 扩展处理，并兼容历史方案。

`CaseReportReview.teaching_plan_v2` 与编辑态 TeachingPlanV2 不是相同投影：报告 steps 为对象数组，且未完整提供 resource_reasons/source_versions。读取报告时不得强转类型或把当前最新方案拼入旧案例。开发先核对 report_service 实际输出；正式案例若缺少必要的材料理由和来源版本，须在报告投影与 HTTP/TypeScript 契约中增加来自该案例所引用复核版本的字段，并同步报告/导出契约测试。这是明确的条件性后端改动，不能仅在前端补一段推测文字。

现有 SourceVerification 已有 knowledge_links、rubric_mappings、resource_links 和 expected_version。必要联系展示优先复用这些已核验字段，不另建平行关系数据。

### 13.3 来源核验必须改到可操作层

当前 SourceVerificationEditor 要求输入“目标指标|关系|依据”等格式，初稿未消除这项学习成本。改为可增删行的表单：指标/材料/节点用真实选项；关系、用途、依据、定位分别输入；评分点问题也按字段编辑。将界面行数据转换为原 payload，保持 expected_version 并发控制。

无效字段显示在对应行，保留输入；遇到版本冲突显示“来源已更新，请比较后重新保存”，禁止自动覆盖。签核成功通过 onSaved 通知要求页、材料目录和全局状态刷新，不能仅刷新编辑器内部历史。

### 13.4 已保存建议不等于已通过建议

阅读状态必须区分 accepted/edited、rejected、needs_observation、未保存草稿和已失效来源。只有已接受或修改并满足有效性条件的版本显示“已复核建议”。驳回版本显示原因并提供重新生成/编辑入口；需观察版本显示观察任务，不标为可正式推荐。正式案例能否引用仍由现有服务端规则决定，界面不能为了走通流程绕过限制。

重新打开已保存建议应允许直接查看；编辑若现有 saveReview 必须绑定 Draft，则明确加载该版本 original_draft 并验证范围/来源，或要求生成当前范围的新草稿后保存新版本。不得用一个空 Draft 绕过校验。增加“读取历史→编辑→保存→重载”验收场景。

### 13.5 首次选择、离开保护与导航恢复

当前 useWorkbench.refresh 默认取首名学生和首个指标，与规划“未选择”状态不一致。实施时可默认展示首个指标目录项，但个人学生须等待用户选择或经验证的链接恢复；节点按现有业务规则处理，所有自动选中均在范围条可见。首页有已复核版本时显示“查看建议/准备案例”，不能再次把用户引回生成草稿。

未保存保护覆盖来源签核、建议、案例和教学调整四类编辑。保存按钮仅在该表单可保存时出现；没有草稿存储能力的无效编辑只提供继续编辑或明确放弃，不能承诺“保存草稿”。切换页面、范围、导入以及浏览器前进后退均走同一保护逻辑；取消恢复旧 URL 和旧内容，不能地址变了而显示仍是旧对象。刷新/关闭用 beforeunload 作浏览器级提示，明确它不能保证异常退出恢复。

EvidenceDetail 关闭不得卸载仍有未保存编辑的工作区。详情有内部编辑时 Escape 先触发离开保护；只读详情才直接关闭。

### 13.6 预检状态与缓存刷新

ReleasePreflight 有 ready、ready_with_open_checks、blocked 三种状态；逐项还有 passed、blocked、not_checked。ready_with_open_checks 显示“可导出，仍有未核验事项”，不能显示“全部完成”。是否允许下载保持服务端规则，PDF/视频/PPT 等外部交付物不因机器预检通过而自动完成。

来源、建议、案例、教学调整保存后，由共同数据刷新入口使相关摘要、报告与预检失效。优先使用明确的更新计数/失效通知和现有请求接口，不引入全新状态管理库。正式下载仍提交服务端 fingerprint，陈旧指纹被拒绝时保留选人并刷新预检。

### 13.7 功能密度与数学内容阅读

全局外壳的范围条和证据链不在开始页同时展开；进入分析页后证据链默认压缩为一行，点击展开，避免头部挤掉首屏。三人报告默认一人完整正文加三人差异摘要，宽屏可提供并排比较；长作答不强制塞进三等宽列。

数学题干、分式、上下标和解题过程必须保持可读。先沿用数据的实际格式，保留换行与符号；只有材料确有公式标记且现有展示不能满足时才评估渲染组件，不把全部文本当 HTML 注入。验收加入长公式、长题干、缺失题干、长表格和打印分页。

主题范围须逐项对照说明会第 7 页与导入资料，页面名称使用资料中的原名，不沿用早期线稿中“几何图形”等未经本题范围确认的示例。独立数据若出现不同数量或班级，不硬编码两班四十人；DC01/DC02 是公开正式展示场景的具体对象。

### 13.8 修订验收与剩余不确定性

增加 useReleaseSelection/useUnsavedChanges 的行为测试及以下真实场景：从交付问题跳出修复再返回；案例引用多个节点而班级报告固定单节点；无评分覆盖证据路径；已驳回建议；来源冲突；ready_with_open_checks；三人选择刷新后恢复且运行不匹配时失效。

本次审查确认并修正了规划中的契约和交互问题，未运行应用测试，也未据此宣称页面效果已验证。尚需开发阶段通过真实接口核对报告投影字段和保存流程，通过试用验证导航与信息密度。已有代码支持或文档描述不能替代这些验收。
