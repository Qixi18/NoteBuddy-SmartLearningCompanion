# 智慧学伴体验规范

## Foundation

本地单用户桌面 Web 工作台。前端为 React + TypeScript + Vite，通过现有 FastAPI API 读取和写入。主要使用者是研发/演示人员；教学方案中的教师复核为必须展示的业务流程。前端按现有 FastAPI 契约实现；需要新增/调整 API 或数据库的能力以待建设占位注明，并在后端契约完成前保持不可用。

## Visual Direction

浅蓝灰工作区画布上使用白色卡片，以浅蓝灰描边和留白分组；品牌蓝只用于当前导航、关键图表和主操作。统计数字与来源状态是页面视觉重点。区块之间留出呼吸空间，单页聚焦当前任务，次要内容交给对应子页面。避免每张卡片使用不同色相、渐变、重阴影和装饰图标。参考样图的导航与卡片结构，但不引入代码中不存在的搜索、通知、成果中心或系统设置。

## Information Architecture

| 页面 | 入口 | 页面职责 | 子页面/视图 |
|---|---|---|---|
| 全局概览 | 应用打开、侧栏 | 查看总体统计、班级摘要和业务入口 | 当前运行、总体指标、班级比较、数据质量摘要 |
| 学科知识 | 侧栏 | 查看课程标准、知识体系、学习目标与题目/教材关联 | 指标总览、指标详情/来源材料 |
| 学情洞察 | 侧栏 | 从班级下钻到学生和作答，检查学习证据 | 班级概览、学生分析、作答证据、数据质量 |
| 教学方案 | 侧栏 | 生成证据约束的建议草稿、教师复核、记录跨运行教学调整并导出案例 | 建议复核、教学调整、案例与导出 |
| 数据导入 | 顶栏“导入数据”或首页空状态 | 输入 CSV 目录并显示导入结果 | 表单、处理中、成功/失败 |
| 赛事覆盖状态 | 全局概览的“当前能力边界”链接 | 让演示人员区分当前功能、待建设项和外部交付物 | 覆盖状态清单；不显示虚构完成率 |

页面层级：

```text
智慧学伴
├─ 全局概览
├─ 学科知识
│  ├─ 指标总览
│  └─ 指标详情 / 来源材料
├─ 学情洞察
│  ├─ 班级概览
│  ├─ 学生分析
│  ├─ 作答证据
│  └─ 数据质量
└─ 教学方案
   ├─ 建议复核
   ├─ 教学调整
   └─ 案例与导出

全局顶部操作：导入数据
```

全局侧栏显示中文主页面，展开当前页面的子导航。用户界面不展示 TASK 编号。浏览器返回/前进恢复页面视图；可使用轻量客户端导航，不添加路由依赖。

## Voice and Tone

短句、准确、克制。使用“待核验”“没有有效记录”“未作答”等明确文案；不使用未经证据支持的“已掌握/未掌握”。

## Component Patterns

- **页面头**：一个页面标题、一行说明和必要的主操作；产品名只在侧栏品牌区出现。
- **全局导入**：通过浏览器目录选择器选择包含六类 CSV 的本地文件夹，检查文件后上传内容到本地后端并新建分析运行；说明源 CSV 不会被移动。界面须准确说明所选文件会上传到本地服务处理。
- **学科知识**：指标列表与来源详情并列或通过子页面查看；未核验状态始终可见。
- **学情洞察**：筛选只影响当前视图；证据行可展开查看作答、评分点和源行。
- **教学方案**：先选学生/指标/节点；无草稿时不显示空白大表单；AI 结果标为待教师复核。
- **案例与导出**：展示候选范围、样本限制；按现有逻辑校验案例数和重复选择。
- **能力边界/占位**：待建设项以“待建设”标签和一句解释显示；如果需要人工材料、独立评测数据或新后端契约，直接说清楚。占位不可触发看似真实的动作。
- **尚无结构化字段的建议理由/优先级/共性问题**：展示“后端尚未提供/尚未核验”的说明，不由客户端把事实重新命名为错误类别或擅自排序推荐。

## State Patterns

| 状态 | 行为 |
|---|---|
| 无运行 | 全局概览解释需要导入六类 CSV，并提供导入入口 |
| 加载中 | 内容区显示与最终内容尺寸接近的加载占位 |
| 运行已加载 | 显示来自 API 的统计摘要和班级比较 |
| 导入处理中/失败 | 防止重复提交；失败时保留输入并显示可操作错误 |
| 来源待核验 | 在学科知识页面标明 pending，不显示成已确认 |
| 节点无有效评分 | 显示“暂无有效已评分记录；这不代表未掌握” |
| 建议草稿未生成 | 显示范围选择和生成入口，隐藏空白编辑表单 |
| 保存复核成功 | 更新版本和历史记录；失败时保留编辑内容 |
| 导出成功/失败 | 给出明确反馈，遵守现有校验 |
| API 错误 | 显示安全错误与重试入口，尽可能保留筛选和编辑内容 |
| 部分支持 | 展示当前可用数据及明确缺项，避免将局部数据说成完整结论 |
| 待建设占位 | 说明当前不可用、需要何种契约/数据；隐藏伪数据、空图表和无效按钮 |
| 独立评测未验证 | 标签保持“未验证”；直到使用组织方数据验证成功后再更新状态 |
| 外部提交物待准备 | 展示 PDF≤20 页、MP4≤5 分钟、答辩 PPT 的独立清单状态；没有文件时不标完成 |

## Interaction and Accessibility

- 导航、筛选、展开和保存均可键盘操作，焦点清晰且切页后落到新页面标题。
- 表格、表单和按钮有可访问名称；错误通过可访问状态播报。
- 状态不能只靠颜色表达；文字对比满足 WCAG AA。
- 不加入无必要动画，并尊重 `prefers-reduced-motion`。

## Responsive & Platform

本轮仅桌面端，主要核验宽度为 1280px、1440px、1920px；紧凑桌面 1024px 保留导航与主要操作。不做平板和手机适配。

## Key Flows

### 全局概览到证据

1. 演示人员打开工作台，先介绍全局统计和班级摘要。
2. 从学情洞察进入班级概览，再选择学生、节点和指标。
3. 打开一条作答证据及源行，说明统计如何回到原始记录。

### 生成并复核教学建议

1. 进入教学方案，选择学生、指标和测验节点。
2. 检查证据、来源状态和推断限制后生成规则草稿；AI 为可选入口。
3. 教师核对只读结构化草稿；编辑诊断、建议、调整条件、复核状态和理由等可持久化字段后保存结论。
4. 历史记录显示对应版本和节点，旧版本不被覆盖。

### 核验案例并导出

1. 演示人员查看三类系统候选，理解候选理由、节点范围和样本限制。
2. 选择某个候选，按证据 ID 打开作答、过程、评分点、班级覆盖和相关建议。
3. 逐个确认案例材料；无证据或类别不符时，保留待补证/待人工说明状态。
4. 选择三名不同学生后查看 ZIP 内容和字段口径说明，再执行导出。
5. 案例完整叙述未完成时，页面明确显示“需人工补充”，不把数据包描述为已完成案例报告。

### 遇到未实现赛题要求

1. 页面显示“待建设”或“未验证”，说明缺的是接口、存储能力还是组织方数据。
2. 仅展示已有证据，不以静态样例数字、默认推荐或虚假完成进度代替。
3. 后端实现并经相应验证后，才能将占位改为可操作内容，并同步更新前后端映射文档。

### 导入新一轮数据

1. 从顶栏或首页空状态选择“导入数据”。
2. 使用浏览器目录选择器选中包含六类 CSV 的文件夹，检查文件清单并确认导入。
3. 查看处理结果；成功后当前运行更新，可进入全局概览和学情洞察。

### 记录教学调整并比较后续证据

1. 选择已有的教师已接受或已修改复核记录，创建教学调整计划。
2. 后续导入新的分析运行后，选择同一学生、指标和节点范围内的证据，记录实际实施、观察结果及可比性判断。
3. 将系统比较视为证据整理；不得仅凭分数变化宣称教学干预有效。

## Confirmed Scope

- 主要使用者：研发/演示人员。
- 目标设备：桌面端。
- 首页优先级：先看全局统计摘要。
- 界面名称和层级遵循用户提供的映射表与侧栏草图。
- 教学方案保留教师人工复核流程。
- 所有赛题未覆盖/未验证要求均以诚实的界面占位表达；本设计文件不等同于功能已完成。
- 前后端契约和赛题覆盖对应关系以 [TASK 01/02/03 实施与验收报告](../development/task01-03-implementation-and-acceptance-report.md) 为准。
