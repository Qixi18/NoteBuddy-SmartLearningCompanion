# 智慧学伴体验规范

## Foundation

本地单用户 Web 工作台。前端为 React + TypeScript + Vite，通过现有 FastAPI API 读取和写入。主要使用者是教师或承担教师复核职责的演示人员；学生可阅读已复核方案，但本轮不提供独立学生账户。需要新增/调整 API 或数据库的能力先明确标注，不以伪数据代替。

## Visual Direction

浅蓝灰工作区画布上使用白色工作面，以留白和浅边框分组；品牌蓝只用于当前导航和主操作。页面重点是用户当前要核对的依据、范围和状态，不让统计抢占工作入口。避免重复卡片、渐变、重阴影和装饰图标。

## Information Architecture

| 页面 | 入口 | 页面职责 | 子页面/视图 |
|---|---|---|---|
| 开始 | 应用打开、侧栏 | 确认当前运行、数据边界并继续工作 | 当前运行、质量提醒、导入数据 |
| 学习要求 | 侧栏 | 核对主题、指标、题目联系和来源 | 指标目录、来源签核详情 |
| 已有表现 | 侧栏 | 查看班级比较、学生表现、原始依据和数据质量 | 班级、学生、证据、质量视图 |
| 学习建议 | 侧栏 | 阅读已保存方案、生成草稿、教师复核和后续观察 | 方案阅读/编辑、观察与调整 |
| 案例与交付 | 侧栏 | 选择案例、核对报告和成果包预检 | 案例准备、阅读报告、交付检查 |
| 数据导入 | 顶栏“导入数据”或空状态 | 选择本地 CSV 目录并显示导入结果 | 表单、处理中、成功/失败 |

页面层级：

```text
智慧学伴
├─ 开始 /home
├─ 学习要求 /requirements
├─ 已有表现 /performance
│  ├─ 班级比较 / 学生分析
│  ├─ 作答证据
│  └─ 数据质量
├─ 学习建议 /recommendations
│  ├─ 阅读 / 编辑复核
│  └─ 观察与调整
└─ 案例与交付 /cases
   ├─ 案例准备
   ├─ 阅读报告
   └─ 交付检查

全局顶部操作：导入数据
```

全局侧栏显示中文主页面。分析范围与案例/班级报告范围分别绑定当前运行；合法选择通过 URL 恢复，URL 不保存作答正文或未保存文本。用户界面不展示 TASK 编号。浏览器返回/前进恢复页面与视图；离开未保存编辑时提示确认。

## Voice and Tone

短句、准确、克制。使用“待核验”“没有有效记录”“未作答”等明确文案；不使用未经证据支持的“已掌握/未掌握”。

## Component Patterns

- **页面头**：一个页面标题、一行说明和必要的主操作；产品名只在侧栏品牌区出现。
- **全局导入**：通过浏览器目录选择器选择包含六类 CSV 的本地文件夹，检查文件后上传内容到本地后端并新建分析运行；说明源 CSV 不会被移动。界面须准确说明所选文件会上传到本地服务处理。
- **学习要求**：指标选择与共享分析范围一致；来源详情中编辑结构化关系，冲突时保留本地输入并要求比较。
- **已有表现**：筛选只影响当前视图；证据详情显示题目、作答、评分点、源行和处置。
- **学生分析**：主视图突出当前节点有效评分、待评分和未作答；事件筛选、排除和隔离等处理细节默认收起。选择学生、指标和节点后，可直接进入同范围建议；无有效评分时入口明确为补充观察，不将缺记录转成学业结论。
- **学习建议**：默认阅读已保存方案；状态区分已接受/修改、驳回、待观察、草稿和来源失效。编辑须使用当前范围草稿，不能用空草稿覆盖历史。
- **案例与交付**：案例学生和班级报告节点在当前运行 URL 中单独保存；候选不自动成为正式案例。
- **能力边界/占位**：待建设项以“待建设”标签和一句解释显示；如果需要人工材料、独立评测数据或新后端契约，直接说清楚。占位不可触发看似真实的动作。
- **尚无结构化字段的建议理由/优先级/共性问题**：展示“后端尚未提供/尚未核验”的说明，不由客户端把事实重新命名为错误类别或擅自排序推荐。

## State Patterns

| 状态 | 行为 |
|---|---|
| 无运行 | 开始页解释需要导入六类 CSV，并提供导入入口 |
| 加载中 | 内容区显示与最终内容尺寸接近的加载占位 |
| 运行已加载 | 显示来自 API 的统计摘要和班级比较 |
| 导入处理中/失败 | 防止重复提交；失败时保留输入并显示可操作错误 |
| OCR文本状态 | 在学习要求页面标明等待解析、解析失败、已提取或该页无文本；OCR提取不自动确认指标与材料关系 |
| 节点无有效评分 | 显示“暂无有效已评分记录；这不代表未掌握” |
| 建议草稿未生成 | 显示范围选择和生成入口，隐藏空白编辑表单 |
| 保存复核成功 | 更新版本和历史记录；失败时保留编辑内容 |
| 未保存编辑 | 页面/范围切换、导入和浏览器前进后退前询问；关闭或刷新显示浏览器提示 |
| 已保存建议 | 只把已接受/修改且来源条件有效的版本标为“已复核建议”；驳回和待观察显示各自状态 |
| 案例范围过期 | 运行 ID 与当前运行不匹配时不恢复旧案例 ID，提示重新选择 |
| 发布预检 | 区分 ready、ready_with_open_checks 与 blocked；逐项区分 passed、not_checked、blocked |
| 导出成功/失败 | 给出明确反馈，遵守现有校验 |
| API 错误 | 显示安全错误与重试入口，尽可能保留筛选和编辑内容 |
| 部分支持 | 展示当前可用数据及明确缺项，避免将局部数据说成完整结论 |
| 待建设占位 | 说明当前不可用、需要何种契约/数据；隐藏伪数据、空图表和无效按钮 |
| 独立评测未验证 | 标签保持“未验证”；直到使用组织方数据验证成功后再更新状态 |
| 外部提交物待准备 | 展示 PDF≤20 页、MP4≤5 分钟、答辩 PPT 的独立清单状态；没有文件时不标完成 |

## Interaction and Accessibility

- 导航、筛选、展开和保存均可键盘操作，焦点清晰且切页后落到新页面标题。
- 证据详情关闭后将焦点交还触发入口；Escape 不得丢弃详情中的未保存内容。
- 表格、表单和按钮有可访问名称；错误通过可访问状态播报。
- 状态不能只靠颜色表达；文字对比满足 WCAG AA。
- 不加入无必要动画，并尊重 `prefers-reduced-motion`。

## Responsive & Platform

桌面优先，主要核验宽度为 1024px、1280px、1440px、1920px。1024px 证据详情转全宽，双列布局堆叠；更窄窗口允许导航换行和表格局部横滚，不承诺完整手机工作台。

## Key Flows

### 学习要求到作答证据

1. 用户从学习要求选择一个真实指标并查看来源核验状态。
2. 进入已有表现，范围摘要继续显示同一指标；用户选择节点、班级或学生。
3. 打开作答证据及源行，返回后范围与视图保持一致。

### 生成并复核教学建议

1. 进入学习建议，选择学生、指标和测验节点；URL 只携带当前运行内的有效 ID。
2. 检查证据、来源状态和推断限制后生成规则草稿；AI 为可选入口。
3. 教师核对只读结构化草稿；编辑诊断、建议、调整条件、复核状态和理由等可持久化字段后保存结论。
4. 历史记录显示对应版本和节点，旧版本不被覆盖。

学生分析页的“形成学习建议”操作直接打开该学生、指标和节点的建议范围；当前范围没有有效评分时显示“补充观察并形成建议”，说明缺少记录不能代表未掌握。教师仍需核对证据后决定草稿内容和复核状态。

### 核验案例并导出

1. 用户查看系统候选，理解候选理由、节点范围和样本限制。
2. 选择某个候选，按证据 ID 打开作答、过程、评分点、班级覆盖和相关建议。
3. 逐个确认案例材料；无证据或类别不符时，保留待补证/待人工说明状态。
4. 选择三名不同学生和班级报告节点；离开案例页或刷新后，当前运行合法范围仍可恢复。
5. 查看服务端预检；存在未核验事项时显示“可导出，仍有未核验事项”，阻断项不能绕过。
5. 案例完整叙述未完成时，页面明确显示“需人工补充”，不把数据包描述为已完成案例报告。

### 遇到未实现赛题要求

1. 页面显示“待建设”或“未验证”，说明缺的是接口、存储能力还是组织方数据。
2. 仅展示已有证据，不以静态样例数字、默认推荐或虚假完成进度代替。
3. 后端实现并经相应验证后，才能将占位改为可操作内容，并同步更新前后端映射文档。

### 导入新一轮数据

1. 从顶栏或首页空状态选择“导入数据”。
2. 使用浏览器目录选择器选中包含六类 CSV 的文件夹，检查文件清单并确认导入。
3. 查看处理结果；成功后当前运行更新并进入开始页，再进入已有表现。

### 记录教学调整并比较后续证据

1. 选择已有的教师已接受或已修改复核记录，创建教学调整计划。
2. 后续导入新的分析运行后，选择同一学生、指标和节点范围内的证据，记录实际实施、观察结果及可比性判断。
3. 将系统比较视为证据整理；不得仅凭分数变化宣称教学干预有效。

## Confirmed Scope

- 主要使用者：教师和承担教师复核的演示人员；学生只阅读已复核任务。
- 目标设备：桌面优先，验证 1024–1920px，并支持窄窗口基本浏览。
- 首页优先级：确认当前运行、范围和下一步；统计摘要来自真实接口。
- 界面名称和层级遵循“学习要求—已有表现—学习建议”及案例与交付。
- 学习建议保留教师人工复核流程。
- 所有赛题未覆盖/未验证要求均以诚实的界面占位表达；本设计文件不等同于功能已完成。
- 前后端契约和赛题覆盖对应关系以 [TASK 01/02/03 实施与验收报告](../development/task01-03-implementation-and-acceptance-report.md) 为准。
