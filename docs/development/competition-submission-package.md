# 竞赛正式成果包

## 操作顺序

1. 导入 CSV 后先完成本地分析；来源 PDF OCR 是单独操作，页面会预览将外发的文件和缓存命中。只有主动确认后才发送未缓存 PDF。
2. 在“指标与来源”中可对当前指标或全部指标运行 AI 映射。模型原文引用和材料编号须通过服务端校验；失败或待处理项不能进入 TASK03 候选。输入或 OCR 内容变化后旧映射失效。
3. 在“教学方案 → 案例与导出”中确认三名学生的正式案例；逐个核对案例叙述、证据引用、教师复核版本和样本限制。
4. 阅读同页的三案例报告和班级报告。正式案例必须来自当前运行的教师确认版本。
5. 在“正式提交发布预检”选择班级报告节点，填写内容负责人，并在重点风险复核后勾选确认。复核聚焦证据引用、异常结论、样本范围、敏感内容和限制说明；无需逐页核验 OCR 文本。
6. 逐项检查发布结果。任一机器检查显示“阻断”时，先按依据补齐数据或签核，再重新预检。
7. 点击“下载正式提交包”。服务器会在同一读取快照上重算预检指纹；运行、案例、复核、来源、AI 映射或报告在预检后变化时，旧请求会被拒绝。

## 包内文件

- `manifest.json`：package type、schema version、运行与案例范围、预检指纹、人工审阅签名和开放检查状态。
- `release_checks.json`：逐项机器检查和人工检查。尚未绑定赛事独立数据时保留`not_checked`，总体状态为`ready_with_open_checks`。
- `case_reports.json`、`class_report.json`、`submission-report.html`：与工作台报告采用同一份运行快照。
- `submission.schema.json`：成果包索引schema。
- `checksums.json`：除自身以外每个ZIP成员的SHA-256。校验时使用文件原始字节计算。
- `ai_indicator_mappings.json`：AI 映射候选、引用、版本和输入指纹；`manifest.json` 列出各指标当前映射版本。
- 原有分析数据、字段与口径说明、复核历史和质量数据文件继续保留。

## 状态解释

- `blocked`：存在会改变成果可信度的机器检查失败，正式导出被拒绝。
- `ready_with_open_checks`：机器检查与内容负责人重点风险复核通过，但官方独立数据或赛事最终验收仍未完成；成果包会显示这一状态。
- `ready`：机器检查与必需人工检查均通过。该状态仍不等于赛事方认可项目效果。

下载后运行 `python scripts/verify_submission.py <成果包.zip>` 校验 ZIP 完整性、JSON 结构和每个成员的 SHA-256。再将 ZIP 自身 SHA-256 写入 `delivery-manifest.md`。该脚本不判定教学内容正确，也不代替独立评测。

正式包会限定三名所选学生的个人级记录；班级文件是被选学生所属班级的聚合数据，可能包括班内其他学生的聚合贡献。不得把该班级聚合数据解释为三名案例学生的个人证据。

个人范围同样适用于未接受建议、教师案例及其历史、教学调整及其历史。发布前服务端会扫描学生级嵌套对象、当前运行证据引用和班级指标明细；超出选择范围或班级聚合中出现逐条记录/事件 ID 时拒绝生成成果包。班级分数、分母和计数保留所选学生所在班级的聚合结果，但不携带个人记录 ID 或事件 ID。旧版导出成员名和 schema 版本保持兼容。
