### 2.3 赛事整体目标与三个任务

赛事以课程标准、配套学习材料和脱敏模拟学情数据为基础，构建可帮助教师理解课程、诊断学习情况并提供个性化学习支持的智慧学伴。评审重输出准确、有据、适切、可核查；不以特定技术、统计模型或推荐顺序作为得分前提。允许多种合理方案；不要求用模拟数据证明真实教学成效。

- TASK01 理解学科：整理三主题的主要学习内容、要求、必要联系与出处；表达范围清楚、准确、便于后续学情分析和建议。参赛说明细化为课标、教材、题目关联。
- TASK02 理解学生：整理并检查数据，说明缺失、异常、重复处理；形成个体和群体摘要，指出表现、待巩固内容、差异、共性和依据；维度要匹配字段，缺记录不得等同没掌握。案例需看题目、作答、得分和步骤。
- TASK03 理解教学：依据学习要求、学情和任务条件，给出具体学习内容、练习/活动、材料、理由、顺序；能实施并可由教师调整；不足时安排补充练习/观察；资源要可定位。案例要求分步提示、不直接给答案并说明后续观察点。

## 6. TASK 03 差距分析

### 6.1 当前代码事实

## 15. 验证与验收策略

- 后端每个新增或修改的业务模块，均有直接覆盖其输入、输出、边界条件的单元/服务测试；持久化模块覆盖约束、重启和回滚。
- 每个新 API 或修改后的 API，均有成功、无效输入、缺失资源和错误响应测试；共享契约样例由前后端读取，字段、枚举、可空性、错误码保持一致。
- 每个被改动的前端组件均有组件测试，关键交互检查加载、空数据、错误和成功状态；集成验收至少跑一次实际前端请求本地真实 API 的完整链路。
- 每个 TASK 至少有一个基于官方资料的黄金用例，人工核对输入、计算过程、证据引用、输出包；清洗/修订行为有边界用例，不能只验证 happy path。
- 导出包从实际流程生成后检查 JSON/CSV 可解析、字段字典一致、来源证据可定位、无内部配置与密钥。
- 验收报告记录命令、环境、结果、未运行项和限制。规划阶段不代表测试已运行或功能已通过；本次分析未运行任何项目测试。
- 课程标准扫描 PDF 按用户要求不做 OCR。相关页码由竞赛 CSV/Excel 给出的定位线索提供，实施验收前由人工对照纸面/可访问原文确认，不把 OCR 准确率作为任务或测试。

### 20.2 数据质量规则

级别定义：BLOCK = 文件/表结构无法安全解释，阻断整个导入；ERROR = 隔离受影响行或事件，不进对应指标；WARN = 保留并统计不受影响的总分，但不得用于有问题的细分分析；INFO = 审计提示，不影响统计。程序不得静默删除或改写源 CSV。

| 异常 | 检测条件 | 级别与动作 | 是否统计/阻断 | 审计 |
|---|---|---|---|---|
| 必需文件/表头缺失、编码错误 | 六表缺失，必需字段表头不存在，UTF-8 解码失败 | BLOCK；拒绝导入并列出文件/字段 | 不创建 run；阻断导入 | 文件名、缺失项、输入哈希（若可得） |
| 行列数量错误、CSV 语法无法解析 | 行字段超出定义列，解析失败 | 当前全文件结构无法可信映射时 BLOCK；若解析库能定位独立坏行则 ERROR 隔离该行及其可识别事件 | 结构不可恢复时阻断；坏行不计 | 源行/解析错误 |
| 必需值缺失/空白 | ID、主题、状态、分数或满分按该字段语义必须存在却空缺 | ERROR；事件/引用缺失隔离受影响记录或事件；待评分/未作答的分数空值是合法状态 | 不计异常记录；不阻断其他独立事件 | 字段名、状态、行号 |
| 数据类型非法 | 整数列不是整数；日期时间非 ISO；枚举未知 | 版本非法隔离事件；分数类型非法隔离事件；模拟时间非法 WARN（不参与排序）；无法解析必要行身份时隔离行 | 仅文件级不可解析时 BLOCK | 原始字符串与规则 |
| 学生/题目/节点引用不存在 | 外键 ID 无对应表行 | ERROR，隔离该事件；不丢原始 CSV | 其余事件继续 | 缺失引用 ID 和源行 |
| 主题/指标与题目冲突 | 作答主题 != 题目主题；题目指标不在课程要求 | ERROR，隔离事件；多指标学习卡不能作为答题材料 | 不计 | 两侧 ID 与值 |
| 题目不在节点可用范围 | Q ID 不属于该节点 allowed items | ERROR，隔离事件；若该节点没有该指标题，标记未测/不可观察而不是低分 | 不计该事件 | 节点题单和题 ID |
| 作答状态/评分状态矛盾 | 已评分却无整数分；待评分/未作答带分数或评分点；未作答仍含实质答案/过程 | ERROR；隔离该事件。待评分有草稿/过程是允许的，不算矛盾 | 不计分；pending/unanswered合法状态按状态计数 | 保留状态及相关原值 |
| 得分/满分范围或类型非法 | 非整数、分数<0或>满分、满分<=0、记录满分 != 题目满分 | ERROR，最高版事件不统计且不回退 | 不计；不阻断整包 | 数值、题目满分、行号 |
| 评分点未知/重复/越界/合计不符 | ID 不属于该题评分点，ID 重复，分值非数值/负/超过该点满分，或评分点和与总分不等 | WARN；保留有效总分指标，禁用该条评分点聚合和评分点驱动建议；如评分点字段是唯一总分来源才转 ERROR，当前赛事有独立总分字段 | 可进总分，不进评分点聚合 | 逐评分点差异、总分差异、源行 |
| 记录编号空/重复 | 非空唯一 ID 约束失败 | ERROR；所有冲突记录所在事件隔离，避免引用歧义 | 不计受影响事件 | 每个重复 ID 与源行 |
| 事件/版本冲突 | 按 20.1 表 | ERROR；隔离事件，不阻断全导入 | 不计 | 保留事件所有行 |
| 空值、未作答、得分为零 | 依官方空值语义和状态枚举 | 分开处理：待评分/未作答无得分；已评分 0 是有效 0 分 | 只有已评分 0 计入分子0、分母满分 | 报表分列，不统一成“未掌握” |
| 题库未覆盖某指标/学生缺记录 | 节点可用题清单和所选数据中无有效评分 | INFO：分别标未教、该节点未测、无记录无法区分漏采/未测；需人工映射确认子主题范围 | 不填 0，不计评分率 | 显示适用题单、可观察状态和 unknown 原因 |

保留两类“合法空值”语义：待评分、未作答的得分/评分点为空不算字段缺失；没有记录不是一条作答为 0 分。统计规则要能输出行号和稳定 finding code，并在 ZIP 的 data_quality 中保留原始行数、选版数、评分有效数、待评分数、未作答数、隔离数、被替代版本数、每类 finding 数。

### 20.3 统计定义与手工复算样例

所有统计先限定一次分析运行及节点、班级/学生、主题/指标/题目过滤条件；默认跨节点不得显示单一得分趋势。下表所说“事件”均指唯一选中版本，且引用/身份/版本合法。

| 指标 | 定义/分子/分母 | 空值与边界 | 能说明/不能说明 |
|---|---|---|---|
| 原始记录数 | 导入 CSV 作答行总数 | 不受选版/清洗影响 | 输入规模，不是学生数或有效样本数 |
| 事件数 | 非空事件 ID 分组数 | ID 空行列为无事件 ID | 不等于已评分数量 |
| 当前版本数 | 可唯一选出最高版本的事件数 | 版本/身份/同版本冲突事件不算可选；内容坏版本仍可作为“已选待隔离”单列 | 版本确定情况 |
| 有效已评分数 n | 满足所有总分统计校验的最高版本事件数 | 待评分、未作答、异常事件不计 | 参与总分比率的观察事件数 |
| 应测数量 | 当前资料没有每个学生实际分配/应答题清单 | **不可计算**。节点“可用题目”只说明允许出现，不证明每名学生都应测每题 | 不报告完成率或应测分母；未来有正式 assignment 表再定义 |
| 有效得分 S | 有效已评分事件的整数得分求和 | 合法 0 分计入 | 已记录得分，不是能力分 |
| 有效满分 M | 同一批有效已评分事件对应满分求和 | 无有效事件时 M=0 | 分母只含真实可评分记录 |
| 得分率 R | S / M | M=0 时为 null/unknown，不写 0% | 该范围有效已评分记录的加权得分比例；不作掌握/因果判断 |
| 题目记录覆盖 | 在指定 cohort+node+主题/指标范围中，至少有一条身份/版本可解释的选中事件的不同题数 ÷ 该节点允许且映射到该范围的不同题数 | 分母为空为 null；也另列有效评分覆盖题数，避免待评题被误当已评分 | 题库覆盖/有无记录，不是学生应试完成率 |
| 指标评分证据覆盖 | 至少有一个有效已评分事件的不同指标数 ÷ 当前节点允许题目映射的不同指标数 | 分母为空为 null；节点未教指标不进入分母；结果附题目映射来源状态 | 有评分证据的指标覆盖，不是掌握率 |
| 学生统计 | 该学生所选范围内的 S、M、n、R；每个指标分别计算 | 无有效分时 n=0、M=0、R=null，并列 pending/unanswered/no-record | 个体已有答题表现 |
| 班级统计 | 班级内所有有效事件 S 之和 / M 之和 | 不取学生比率简单平均；同时展示有效学生数、事件数、题目覆盖和分布 | 班级记录摘要；不以均值排序作学生标签 |
| 节点统计 | 同一 node_id 内按上述分层公式汇总 | N01/N02分开展示 | 两节点题目和教学范围不同；直接差值不是学习进步 |
| 未教/未测/无记录/未作答/待评分/已评分零分 | 由节点说明、允许题映射、实际选中事件状态分别标记 | 不能互相填充或合并 | 状态事实；任何一种都不自动代表“不掌握” |

“题目记录覆盖”不是“应测完成率”。题目目录中同一指标可能有多题；学生未出现某题记录时，只能说“未观察到该题记录”，在没有逐生 assignment 清单时不能判定漏交。班级有题记录覆盖可作群体层面覆盖描述，仍不能推断每位学生应答了全部可用题。

**可手算黄金样例（测试规划，未执行）：** 构造 N01 某学生的同一指标可用题 Q001—Q005。当前事件为 Q001=1/1、Q002=0/1、Q003=待评分、Q004=未作答；Q005无记录。预期：有效评分数 n=2，S=1，M=2，R=50%；待评分=1，未作答=1；有效评分题覆盖=2/5；任何一项都不能解释成该生“掌握50%”。如把 Q002 的 0 分记录改成缺失，不得增加零分或仍报告 R=50%，而是有效评分 n=1、S=1、M=1、R=100%，同时覆盖率降低。若节点/指标交集为空，R 与 coverage 均为 null。

### 20.4 评分点与作答步骤

官方数据形态为两张表的文本字段，不是已规范化评分点关系表：

- 题目与材料.csv 的“评分点”每行一个评分点，含评分点编号、内容、分值；编号按题目编号加 P 序号。
- 作答记录.csv 的“评分点得分”是编号=所得分的分隔字符串。
- “解答过程”是按 1.、2. 编号的自由文本；数据没有评分点—步骤编号外键、错误代码或独立可靠的概念误解标签。
- “得分”是独立的已评分总分。官方没有说明总分必须由逐点评分自动相加；项目采用校验求和、保留两列证据的做法是工程建议，不是把当前评分点反推成官方计分规则。

确定性计算只做：对合法最新事件解析评分点 ID/所得分；校验该 ID 属于题目、未重复、分数可解析且处在该点分值范围内；该题各点完整且求和与总分一致时，按「某题某评分点所得分之和 / 该评分点可得分之和」统计，并同时报告有效事件数、学生数和缺失/冲突数。若一点按题目配置满分1，得分为0/1时示例聚合率就是 sum(points earned)/number of valid rated point observations；若各题同一指标下评分点语义不同，禁止跨 ID 合并，先由 TASK01 人工建立已核验的共享“问题表现映射”，否则只按题目/评分点 ID 分列。评分点不一致行不进入该评分点聚合，但在总分通过校验时可保留总分统计并告警。

**步骤关联规则：** 存储原始步骤文本、原记录 ID、source line、题目评分点定义和评分点数值；仅当人工整理的题目专属 rubric→step locator 映射存在且经核验时，展示“该步骤对应这一评分点”。没有该映射时只并列展示步骤和评分点结果，结论写“该评分点未得分/部分得分”，不写“因为第 N 步的概念错误”。不得使用关键词匹配充当数学错误分类器。

**可复算评分点样例（测试规划，未执行）：** Q006 的 P1/P2/P3 各满分1。唯一当前记录为总分2/3，逐点 P1=1、P2=1、P3=0：三点各自记录为1/1、1/1、0/1；P3 可表述为“该题 P3 评分点未得分”；不能据此自动断言具体步骤或概念错误。若总分写3但点分合计2，则总分和满分校验通过时总分仍按3/3计入总体，finding 标示评分点冲突，该记录不进入评分点聚合。官方公开数据 DR0133 正是需此处理的示例。

## 21. TASK03 确定性推荐策略

### 21.1 规则原则和证据顺序

主规则链是：TASK02 已校验的学生—节点—作答记录 → 可直接核验的得分/评分点表现 → TASK01 已审核的课程指标 → 同节点已教范围内、经人工核验的教材/学习卡 → 不泄露答案的练习活动 → 观察点和调整条件。TASK03 不重算得分，不通过固定阈值把得分率划分为能力等级。

当前 recommendation_service.py 的问题及最终取舍：

1. 固定 0.6 没有赛题或公开数据验证依据；移除巩固/变式的 0.6 二分，不以另一条隐蔽百分比阈值替代。
2. _evidence 取合并 N01/N02 的 student_indicator 指标和两节点记录；先按 node scope 过滤再推荐，否则只给“需要教师选择范围”的 unknown。
3. materials[0] 取同指标第一题不能说明该题是教学材料，也没有证据对应性；先选 TASK01 人工核验的学习卡/教材条目，再选节点允许且适合练习的题。无已核验映射时只给可执行的观察/补测模板，不臆造来源。
4. rubric 解析零分点只作为可观察的“评分点未得分”事实；一致性校验通过前不将它当特定错误类型。
5. DeepSeek 保持单一轻量 LLM Protocol 和 DeepSeek Adapter。TASK02 算统计，TASK01 提供来源，TASK03 负责规则建议；模型只帮表述，不负责事实选择、得分、材料 ID 或最终判断，所有建议需教师复核。

推荐统一门槛字段：run_id、student_id、node_id、indicator_id、evidence_record_ids、evidence_kind、observed_fact、inference_limit、material_ids/source_locator、steps、observation_point、adjustment_condition、rule_id、status=needs_review。添加字段时保持已有 DraftResponse 的现有字段可读，旧客户端仍能读取旧响应字段；需新契约测试。

### 21.2 推荐决策矩阵（8 条）

### 21.3 DeepSeek 约束与测试矩阵

自动结构校验可拒绝：非法 JSON/缺字段、引用 ID 不在已给学生与指标允许集、引用其他学生/指标的记录、虚构材料 ID、未知 node、已有参考答案原文作为模型输出字段。参考答案不得放入生成请求；只给必要的题目证据摘要和已核验资源名称/locator。语义上是否泄露答案、是否数学正确、是否教育伦理合适不能靠 schema 或关键词完整判断，必须教师查看草稿并决定接受/修改/拒绝。

| 模型负例 | 自动措施 | 人工复核 | 测试计划 |
|---|---|---|---|
| 虚构 evidence ID | 集合子集校验拒绝整份模型草稿 | 查明模型收到的证据范围 | 返回安全错误，不落复核历史 |
| 引用其他学生记录 | 允许集合以 student_id+node+indicator 构建 | 检查同生同范围 | 即使 record ID 真实但属他人也拒绝 |
| 引用其他指标记录 | 允许集合再以 indicator/material map 过滤 | 查跨指标映射误差 | 其他指标 evidence 拒绝 |
| 直接给最终答案 | 请求不发送参考答案；结构输出将答案当提示词字段拒绝不了所有语义形式 | 教师判定提示是否实质泄题 | Mock 直接答案样例须进入人工审查状态，不可自动 accepted |
| 来源无法定位 | material_ids/source_locator 只能从允许列表选择 | 核对教材内容对应性 | 虚构 Bxx/页码结构校验拒绝 |
| JSON 契约错误/多余字段 | Pydantic/schema extra forbid 或白名单投影；失败丢弃模型草稿 | 记录模型失败原因，不影响规则基线 | malformed/缺字段/错误类型均失败关闭 |
| 与数据证据矛盾 | 对分数、状态和 ID 引用做结构交叉校验 | 数学结论、误解标签由教师审阅 | 写出与 score/rubric 相反文本时不得自动通过 |

模型 Adapter 无 Provider Registry、多模型调度或复杂重试。模型网络错误返回现有确定性 draft 或明确失败提示，不覆盖规则基线，不保存未经教师选择的输出为最终结果。

## 26. 正式开发准备结论

### 最终检查

- 目标代码目录均以现有真实路径为基准；拟新增文件已明确标识，且仅在映射无法由现有CSV表达、存在实际调用者时新增。
- 模块边界：Domain放纯教育事实/规则；Application只编排Ports/Use Case；Services分别承担 TASK01关系校验、TASK02唯一统计口径、TASK03决策；Infrastructure适配CSV/SQLite/本地文件/DeepSeek；API和前端只呈现契约。不需要新建大型Domain/Application子系统。
- 依赖只有 TASK01→TASK02→TASK03；TASK03不重算统计，模型不能重建证据；不把课程PDF解析变成OCR范围。
- TASK02所有统计先确定事件版本，再验数据；高版本坏即隔离、绝不回退；应测量无法由当前资料计算；分数、状态、coverage独立；N01/N02不直接比较增长。
- TASK03不用固定 0.6；最终有 8 条规则 TR-01..TR-08、优先序和每条测试；无新推荐分数/掌握标签。
- 21 项软件开发任务 + 4 项参赛交付任务，ID保留且类型区分；依赖图无环；每个软件任务均列真实基线、文件范围、层次、兼容、依赖、测试和验收。
- 数据库预计不新增表、不新增 Alembic migration；当前快照、规范化作答和 teacher_reviews 足够。仅未来独立生命周期事实另行评审，不能预先建表。
- 无CI/GitHub Actions要求；测试在本地阶段执行。每个改动要记录原因/兼容性/对应测试；现有三个TASK API入口/CSV语义/快照/ZIP/复核历史必须回归保持。
- 本轮检查只读了代码与官方可提取文本；没有执行测试。公开材料的确定性异常已写入测试规划，不能说测试通过。

### 尚待人工确认、对正式开发的影响

1. Phase 0需由团队负责人接受或调整20.1/20.2所列“项目建议策略”（尤其坏版本隔离、同版本重复、评分点冲突）。赛事未规定这些异常的唯一算法；在策略冻结前阻断TASK02算法正式开发。
2. TASK01需由数学学科成员核对 CR01—03页码、54题到9指标、学习卡/教材切片定位和先修关系；尤其N01的T02I3测量范围及T02I2未教状态。阻断依赖争议映射的TASK03选材，但不阻断现有字段读取与无争议关系校验。
3. 根 resources/source_checks.json 当前把 B02 同时挂在 T02/T03；B02 切片内容是 T03 不等式。TASK01应确认并修正这项项目映射，不把它写成赛事官方要求；修正/签核前禁止将 B02 作为 T02 来源。
4. 独立评测数据和赛方后续版本/提交时间尚未提供；不阻断公开样例上的功能开发，但阻断独立评测结论和最终提交日程确认。
5. 模型自然语言语义风险无法完全自动验收；深度模型调用可由团队选择不启用，但赛题安全要求下模型输出必须教师审核，不能以mock测试代替实际人工审核流程。
6. 课程标准扫描件页码由人工确认，按用户明确范围不做OCR、不设置OCR功能或OCR测试。

### 结论：CONDITIONALLY READY

规划已达到可按Phase 0开始正式开发准备的程度；不建议在数据决策未签核时直接实现TASK02核心统计。可并行启动无争议的TASK01人工核对和关系完整性工作；TASK02实现需先冻结版本/异常/评分点策略，TASK03材料选择需等待TASK01映射核验。故结论为 **CONDITIONALLY READY**，不是“全部业务规则均由官方明确”或“测试已通过”。确认 Phase0 决策并完成人工来源签核后，可按无环阶段计划推进；本次到此停止，不开始业务代码开发。
