# 性能基线（2026-11-20）

## 结论

在本机使用赛题提供的六份模拟学情 CSV 生成合成压力样本，并分别执行 5 次完整后端流程。1000 行与 5000 行均成功完成数据库迁移、导入、证据查询、三案例报告和班级报告。5000 行数据的导入中位数为 1.179 秒；证据接口中位数为 83 毫秒；案例/班级报告中位数为 88/91 毫秒。当前结果不支持立即改动统计、导入或缓存逻辑；下一步应在实际演示电脑补充浏览器交互与首次使用者观察。

## 环境和数据

- 时间：2026-11-20（本地执行）
- 系统：Windows 11，build 26340
- Python：3.13.3（项目声明支持 Python 3.12 及以上）
- CPU：Intel64 Family 6 Model 198 Stepping 2；24 个逻辑处理器
- 基准脚本：`scripts/benchmark_competition.py`
- 样本来源：赛事资料包的 `模拟学情数据` 六份 CSV。原文件只读；基准先克隆完整作答事件及其修订组，生成目标 1000/5000 行样本。克隆行不是新增学生证据，也不是独立或隐藏评测集。
- 每次测量在新的临时目录创建 SQLite 数据库，执行 Alembic `upgrade head`，导入样本，随后通过应用的 FastAPI 工厂请求接口。每次结束后删除临时数据库和数据。
- 六份来源文件的 SHA-256 均与 `tests/fixtures/competition/official-baseline.json` 一致。该一致性证明基准读取了已记录的资料包原件；不代表样本经赛事独立评测。

## 解读与未覆盖项

这是单台开发机的后端基线，没有定义或声称达到正式性能 SLA。第一次导入和多次重复测量之间可能受操作系统文件缓存、SQLite 和进程内暖机影响；各轮都使用全新数据库，但不重启操作系统。这里的“启动”分别指 Alembic 迁移、Store 构造和健康接口请求，不等于用户电脑冷启动整个桌面服务。

本次未测浏览器切页、展开长证据、打印/PDF、刷新恢复、前端冷启动，也未进行三名首次使用者的任务观察。下一项应在目标演示电脑使用浏览器记录完整的“导入→证据→编辑方案→确认案例→导出”流程，再据此决定是否优化。可访问性、键盘焦点和表单错误检查仍需独立完成。性能测量通过不等于易用性、数学内容或教学效果验收通过。

未发现足以支持缓存或统计改造的证据。本次不添加缓存，避免引入运行/来源版本失效风险，也不以变更分母或评分口径换取速度。
