# 赛题提交放行清单

本清单把工程检查、学科内容复核和正式文件核对分开。任一必交项缺失、任一正式案例未签核或输入版本无法追溯时，状态保持 `not_ready`。技术门禁通过不代表教学内容通过。

## A. 赛事硬性要求

依据《1_赛题规则.pdf》第3–6、8–9页及《3_典型案例说明.docx》：

- [ ] 设计方案 PDF 不超过20页；包含需求分析、方案设计、功能说明、结果验证、创新点、使用平台与方式、数据范围和关键结果依据。
- [ ] 任务成果包包含 TASK01 学习内容梳理、TASK02 个体与群体分析、TASK03 个性化建议；结构化输出附字段说明、输入输出样例和操作说明。
- [ ] 演示视频为 MP4，时长不超过5分钟；展示三项核心任务、三案例、建议及依据查看方式。
- [ ] 现场答辩 PPT 支持10分钟讲解；准备5分钟问答。分析代码可选，但关键结果输入和对应输出必须可核对。
- [ ] 正式案例来自 D01–D40，选取三名代表性学生；报告比较 DC01、DC02 两个模拟班。
- [ ] 视频、PDF 和 PPT 使用同一冻结运行、同一三名案例、同一发布指纹；不混用旧截图或旧统计。

## B. 数据与复核门禁

### G0 输入冻结

- [ ] 记录六张输入 CSV 的 SHA-256、行数、运行 ID、`rule_version` 和分析时间。
- [ ] 806条作答记录的处置数守恒；当前已知赛事基线为 786 scored、5 unanswered、7 superseded、4 excluded、4 pending；得分与满分为 744/1304。
- [ ] 运行独立复算脚本并与 `tests/fixtures/competition/official-baseline.json` 对照。
- [ ] 明确说明该数据是赛事公开提供的模拟开发/展示数据，不是独立评测集；独立评测数据当前不在本项目资料目录。
- [ ] 赛事资料仅用于本次比赛；不得加入真实学生个人信息。赛后按赛题组要求删除。

### G1 TASK01 学习内容与来源

- [ ] 9项指标逐项核对课程标准文件页、正文条款、教材册次和印刷页。
- [ ] 54道题逐题核对主题、指标、材料类型、题干和评分点；不能把8项教材索引及3张学习卡当成试题。
- [ ] 8项教材和3张学习卡检查材料类别、用途、适用范围和定位；检查 PDF 原件哈希。
- [ ] 必要联系需写出关系和依据；没有依据的关系不进入正式图谱或推荐理由。
- [ ] 由数学内容负责人签核；文件变化后旧签核不得继续用于当前发布。

### G2 TASK02 学情与统计

- [ ] 每个重要事实能追溯到学生、节点、题目、来源行和处置状态。
- [ ] 两班对比说明共同题目集合、覆盖人数和有效分母；不因覆盖不同直接排名。
- [ ] 分节点呈现 N01、N02；不把两个不同测验节点差异解释为学习进步。
- [ ] 明确区分零分、满分、部分得分、待评分、未作答、无记录和异常；信息不足不转成未掌握结论。
- [ ] 个体案例中的答题步骤由内容负责人抽查，评分点事实与总分事实分开表达。

### G3 TASK03 学习建议

- [ ] 每条建议关联具体材料编号、材料用途、适用范围和选择理由。
- [ ] 写清教学顺序、分步提示、补充观察或练习、观察点和调整条件；提示不直接泄露答案。
- [ ] 未核验来源不得进入正式推荐；规则草稿与模型草稿清楚标识，教师复核留有版本历史。
- [ ] 正式案例建议经数学/教学负责人签核；不得把模拟数据包装成真实教学成效。

### G4 三案例和班级报告

- [ ] 三名正式案例均在当前运行被教师确认，且报告中的案例 ID 与最终 ZIP 一致。
- [ ] 对部分得分、相对较好表现、记录不足三种需求形成差异化解释；候选 D04、D36、D17 只有通过内容负责人审核后才能成为正式案例。
- [ ] 班级报告能独立阅读，人数可从去重学生清单复算，分母和限制清楚。
- [ ] 内容负责人对三案例和班级报告进行重点风险复核，记录姓名、日期和版本指纹；聚焦异常结论、证据引用、样本覆盖、敏感内容及限制说明，不要求逐页核验 OCR 文本。

## C. 工程与成果包门禁

- [ ] 服务端发布预检无阻断项；未完成的独立数据评测保持 `not_checked`，状态不得写成全部通过。
- [ ] 预检和正式导出引用同一当前运行快照；运行、来源、案例或复核变化会使旧指纹失效。
- [ ] 解压 ZIP，检查所选三人范围、班级报告、JSON schema、字段说明、HTML/PDF 可读性和成员 SHA-256。
- [ ] 对学生级文件及嵌套建议/复核/调整记录扫描范围泄漏；所有证据引用在包中闭合。
- [ ] 输入输出样例使用合成数据；不把其他学生个人明细带入三人提交包。
- [ ] 保存正式 ZIP SHA-256、源码 commit、运行 ID、输入哈希和人工签核记录。

## D. 现场演示门禁

- [ ] 干净目录或演示机完成迁移、启动、导入和浏览；不依赖本机开发环境隐式状态。
- [ ] PDF 来源预览可访问；断网时规则方案和已确认案例仍能演示。
- [ ] 现场只监听 loopback；关闭或清空模型密钥，除非已按费用与数据发送政策批准实际模型调用。
- [ ] 录制完整五分钟以内视频，现场 PPT 计时不超过10分钟；至少进行一次完整问答演练。
- [ ] 备用方案：预录视频、已校验成果包、逐页截图、运行指纹与启动命令均在同一冻结版本下。
- [ ] 工程、数学内容、交付三方分别记录验收状态。内容负责人缺席时，不可由工程检查替代签核。
