# 智慧学伴前端可读性与页面布局专项优化 · 验收记录

- 验收时间：2026-11-27
- 分支：`feat/optimize-fonts-layout`
- 基线：`b85f515`（与 main 同一提交，本轮从零开始）
- 环境：Windows / Python 3.12 / Node 24 / Edge（Playwright channel=msedge）
- 范围：九页教师端前端；后端接口、数据口径、AI 调用/审核/持久化逻辑未改动

## 1. 本轮目标与边界

本轮不是整体 UI 重建，而是围绕教师长时间阅读、分析数据和填写教学方案，做两件事：

1. 建立统一的字号、行高、间距和布局变量，替换各 CSS Module 中 8–11px 的局部写死字号。
2. 按内容重要性重新分配空间：核心图表和阅读区获得更大宽度；低内容模块、空状态和长列表通过压缩、折叠、筛选、分页控制密度。

保留项：绿色配色、九页业务结构、全部教师操作、后端接口、数据语义。
未做项：知识图谱库、新字体家族、CSS 文件大规模拆分（保留原文件，按模块增加专属布局类）。

## 2. 已落地的改动

### 2.1 全局基础

- `apps/web/src/styles/tokens.css`
  - 新增 `--font-size-xs/sm/label/body/md/lg/panel/stat-sm/stat/hero`。
  - 新增行高、4/8/12/16/20/24/32 间距变量。
  - 侧栏 224px、折叠 64px、顶栏 64px、内容最大 1800px、面板内边距 24px、卡片间距 20px、控件高度 42px。
  - 全部颜色变量保持不变。
- `apps/web/src/styles/global.css`
  - 正文默认 15px / 行高 1.5；表单元素统一继承；补充 textarea/summary 焦点样式。
- `AppLayout.module.css`
  - 顶栏筛选器、二级菜单、教师信息、页标题提升到 13–16px。
  - 860px 以下不再靠缩小字体适配，改为换行/折叠；650px 以下隐藏静态通知/教师信息入口，保留侧栏教师信息。
- `PageBits.module.css` / `PageBits.tsx`
  - 面板标题 20px、正文/提示 15px、表头 14px、表格正文 15px。
  - Metric 支持 `variant="text"`，长文本指标可换行，不再被 27px + ellipsis 截断。
  - EmptyState / Loading 支持 `compact`，用于小模块和空状态。

### 2.2 教学工作台

- 12 列网格：主题表现 8 列 + 优先事项 4 列；候选/分布 6+6；AI/快捷入口 4+8；质量/导出/发布全宽。
- 图表高度 245 → 340px；纵轴 100px → 150px、允许换行、字号 13px；横轴 12px 并隐藏重叠标签。
- 优先事项标题允许换行；标签、辅助说明提升到 12–13px。
- 无模型时 AI 卡片使用 compact 变体，避免与图表同高产生大块留白。
- 赛事发布在无已确认案例时使用 compact 空状态，并隐藏无用的负责人/勾选表单；保留禁用导出按钮，便于教师理解当前不可执行。
- 1250px 以下改为双列，快捷入口独占整行；1024px 以下保持双列。

### 2.4 学情诊断

- 班级诊断：
  - 从 1.16/1.16/.86 三列改为“图表 + 共性问题”两列，数据质量下移为全宽。
  - 图表高度 270 → 340px，纵轴 90 → 150px，字号 9–10 → 13px。
  - 关键题目证据改为两列，避免半宽面板内继续三列挤压。
  - 移动端表格改为内部横向滚动，不再把列压成竖排文字。

- 题目证据详情：题干、作答、评分依据保留完整阅读宽度，正文 15–16px；关键事实 14px；本题关联的诊断观察提前到“评分数据核查 / 相似证据”之前，形成先看题目与作答、再看诊断观察、最后看质量与班级对比的阅读顺序。

### 2.5 教学建议

- 学生个性化建议：
  - 60:40 布局；草稿/审核表单在左，证据与资源在右。
  - 表单输入 15px、最小高度 42px；长文本字段整行。
  - AI 证据分析移动到“教学实施与调整记录”之前，保持“先分析、后实施”的阅读顺序；AI 调用/确认/持久化逻辑未改。
- 班级教学建议：
  - 报告/方案使用独立的 55:45 布局类，不再直接共用通用双栏。
  - 方案版本历史改为可折叠区域。
  - 报告内部“已核验共性观察 / 课程来源映射状态”改为单列堆叠，来源映射表不再挤压。
- 实施与复测空状态使用 compact 变体，减少无方案/无记录时的大块空白。

## 4. 已知限制与后续

1. **200% 缩放的自动化是等效视口验证**：1440×900 在 200% 下按 720×450 CSS 像素处理，不是真实 Ctrl+ 浏览器缩放；真实浏览器缩放仍建议人工抽查一次。
2. **正式数据截图使用本地临时导入脚本生成**，没有把正式 CSV 复制进仓库；截图已保留，测试 fixture 仍使用 `demo-data/csv`。
3. **未做 CSS 文件拆分**：`WorkbenchPages.module.css` 仍是共享文件，本轮通过专属布局类降低耦合；如果后续继续扩展，再按 Knowledge/Diagnosis/Teaching 分文件迁移。
4. **移动端复杂表格仍为横向滚动**：这是保留全部列和数据的折中；若赛事评审更强调手机端，可进一步做卡片化表格。
5. **正式数据中“学习要求”文本为空**：界面按数据现状显示“当前数据未提供独立的学习要求文本”，没有推测填充。
