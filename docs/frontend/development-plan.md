# Web 前端重建设计与阶段计划

## 目标

以 `docs/frontend/design/` 中九张定稿图为视觉基准，重建教师教学 Web 前端。所有统计、诊断、证据和建议均来自现有 FastAPI 接口；空运行时显示导入引导，不展示设计稿中的示例数字。四个业务模块共用一套导航和教学范围。

## 工程方案

- React、TypeScript、Vite、React Router Hash 路由。
- TanStack Query 管理接口数据与失效刷新；ECharts 绘制统计图。
- CSS Modules 与 CSS 自定义属性实现设计系统，Lucide React 提供图标。
- URL 保存 `node`、`student`、`indicator` 等分析范围。API 层集中封装请求和错误处理。
- Vite 开发时代理 `/api` 到本机 FastAPI；生产构建由 FastAPI 在 `/` 和 `/assets/*` 提供。

## 页面结构

教学工作台；课程知识（主题概览、知识结构、题目关联）；学情诊断（班级诊断、学生个人诊断、题目证据详情）；教学建议（学生个性化建议、班级教学建议）。所有页面共用侧栏、顶部学科/班级/测验选择器和内容框架。

## 实施阶段

1. 前端基础、共享框架与真实数据教学工作台。
2. 主题概览、知识结构、题目关联与来源核验。
3. 班级诊断、学生诊断、题目证据追溯。
4. 学生及班级教学建议，接通复核和调整记录。
5. AI、数据治理、赛事报告和成果导出操作界面。
6. 全页面浏览器验收、响应式与视觉对照。

班级 AI 建议的后端请求当前没有 `class_id`。联调前不得把节点范围结果标记为班级专属建议；只有确认缺口后再补充最小后端能力。分数比较必须显示共同题目口径和覆盖限制，缺失记录不视为零分。

## 本阶段交付

创建可启动、可构建的前端工程和共享导航；首页加载 `/api/run`、`/api/readiness`、`/api/class-insights`、`/api/cases` 等真实数据；支持首次导入提示、文件导入、班级/测验范围切换及教学建议导航。后续页面沿用该框架逐步完成。

## 当前实现进度

- 阶段 1–4：教学工作台、课程主题/结构/题目、班级与学生诊断、证据详情、学生建议复核及学生教学调整已接入现有接口。
- 主题概览表已把学习要求、观察指标、关联题目编号、教材来源定位和教师核验状态放在同一行追溯；缺少源数据时显示未提供状态，不补造内容。定位文本标明“合成验收数据”的核验记录现在显示为“含合成验收记录”，来源目录同步标出合成状态，避免把流程记录误读成真实教材已核验。
- 首页视觉对照后，将完整数据质量面板下移至主题表现、优先事项、助手、学生候选、班级分布和快捷入口之后，避免挤压主教学概览；优先指标图标回归定稿图的绿色主色。质量说明条仍保留在首屏指标区。
- 知识结构页已展示所选指标详情和真实关联题目；关联题目及学生诊断中的证据引用可以直达对应题目的证据详情，并保留学生、指标、班级和测验范围。
- 知识结构页已按定稿层级重排为主题导航、课程指标关系图和当前指标详情，并增加主题指标/题目/有效来源核验汇总；中部连线只表示真实主题归属，教师核验的前置关系与候选关系分开展示。当前隔离运行只有 1 个主题、1 项指标，暂不能验证多主题、多指标关系图的拥挤和切换表现。
- 学生诊断页展示当前范围的有效评分记录数、有效评分题目覆盖、已评分记录得分率、证据质量提示及逐条得分进度；指标只按证据包中的有效评分记录计算，并明确不代表整体掌握程度。
- 阶段 5：已加入学生范围 AI 分析预览与显式传输确认、数据质量明细、三名学生案例资料包导出、结构化教师方案、正式案例确认、赛事发布预检和带指纹校验的正式材料导出。
- 正式案例确认要求当前有效来源核验、已接受的结构化教学方案和可追溯作答证据；页面不能满足这些条件时会禁用确认操作。
- 正式导出按后端预检返回的当前运行与指纹执行。独立人工验收仍由赛事流程负责；即使后端允许导出，页面也会标明尚未完成的开放检查。
- 生产静态文件输出到 `apps/web/dist`，与 FastAPI 默认静态目录保持一致。
